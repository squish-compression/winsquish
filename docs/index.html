A file manager for SQUISH archives

What it does

Browse

An Explorer-style layout: folder tree, details list with name · type · size · packed size · % saved, breadcrumb, status bar. Folder rows aggregate the sizes and ratios of everything beneath them.

Extract

The whole archive, a selected subtree, or a single file. Multi-select with Ctrl/Shift, Ctrl+A for all, or drag files straight out of the window into Explorer.

Preview

Double-click a file and it is extracted to a temp folder and opened in its default app. Save As writes a single file wherever you choose.

Create

Compress a folder into a new archive using every core, with a dialog for block size and thread count before the run starts.

Edit

Drop files or folders onto an open archive to add them at the current location, or select and press Delete to remove them. Name clashes prompt; on any failure the original archive is left untouched.

Drag & drop

Drop an archive on the window to open it. Drag members out to Explorer to extract them. It works the direction you expect, both ways.

Lives in the shell

WinSquish registers itself as the handler for .sqsh and .sq and adds right-click menus, so most of the time you never open the app on purpose.

  • On an archive — Open with WinSquish, Extract Here, Extract to folder\
  • On any folder — Compress to SQUISH archive
  • Each verb is a one-shot action with its own progress window

The app writes the registry keys itself, so the installer just calls it — and you can do the same without admin rights: 

WinSquish.exe --register            :: current user
WinSquish.exe --register --allusers :: machine-wide
WinSquish.exe --unregister

Or click “Make WinSquish the default for .sqsh files” on the welcome screen.

Or from a prompt

Every GUI action has a command-line twin.

WinSquish.exe archive.sqsh
:: open & browse

WinSquish.exe --extract-here a.sqsh
:: extract into the archive's own folder

WinSquish.exe --extract-to a.sqsh
:: extract into a subfolder named after it

WinSquish.exe --compress path
:: compress a file or folder to path.sqsh

Add --quiet to the register/unregister calls to suppress the confirmation dialog.

Install

Installer

Grab winsquish-setup.exe from the releases page. It installs a self-contained build, offers per-user or all-users scope, wires up the file associations and context menus, and unregisters cleanly when you uninstall.

Latest release

Signing

The app binaries, the installer and its embedded uninstaller are all signed with Azure Trusted Signing — SHA-256 and RFC-3161 timestamped — so Windows knows where they came from.

Build it yourself

WPF on .NET 10, driving the native libsquish (squish.dll) through a thin P/Invoke layer. 

dotnet build -c Release
dotnet run --project src -c Release

# open an archive straight away
dotnet run --project src -c Release -- path\to\archive.sqsh

# squish.dll somewhere else?
dotnet build -c Release -p:SquishDll=C:\path\to\squish.dll

The installer needs Inno Setup 6.3+; then installer\build-installer.bat produces build\winsquish-setup.exe.

How it fits together

src/
  Interop/     P/Invoke over squish.dll
  Models/      entry list -> browsable tree
  Shell/       file types + Explorer verbs
  ViewModels/  archive, navigation, async ops
  Views/       toolbar · tree · details · overlay
  Themes/      the light "fluent" theme
installer/     Inno Setup script + signing

Every libsquish call funnels through one wrapper that serializes them on the handle. Open, extract and create run on a background thread and report into a busy overlay. The entry index is read eagerly at open, so browsing is instant and only extraction ever touches compressed data.

One honest caveat

SQUISH trades CPU for ratio — roughly 0.5–0.7 MB/s, symmetric in both directions. Extracting or creating a large archive takes real time, and the progress overlay shows bytes and throughput so you can watch it happen. What you get back is a much smaller file.
